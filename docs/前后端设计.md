# 「共鸣」前后端技术设计

> 版本 v0.1 · 2026-11-12 · 单人快速上线优先

## 0. 结论速览

| 项 | 选择 |
|----|------|
| 形态 | Web 优先（响应式，手机浏览器可用），验证后再做 App（Expo） |
| 前端 | Next.js（App Router）+ TypeScript + Tailwind CSS |
| 后端 | Supabase（Postgres + Auth + Realtime + Storage）+ Next.js API Routes |
| AI | DeepSeek API（成本极低）；画像/匹配走固定规则脚本，AI 只做「关系复盘解释 + 开放式提问」的点睛 |
| 内容审核 | 国内：腾讯云/阿里云内容安全；起步先「人工 + 举报」 |
| 部署 | Vercel（前端）+ Supabase（托管） |
| 备案 | 国内上线需 ICP 备案 + 婚恋平台资质，写代码前专项调研 |

## 1. 技术选型理由

- **Next.js**：前后端一体，一套代码同时出页面 + 接口，SEO 友好（社区/百科内容可被搜索），Vercel 免费部署，单人效率最高。
- **Supabase**：自带 Postgres、邮箱/手机/第三方登录、行级安全（RLS）、实时订阅、文件存储，省掉 80% 后端样板代码；免费额度足够 MVP。
- **DeepSeek API**：成本极低（国内直连、中文强）。核心原则：**AI 不产出人格结论，只把结构化数据翻译成人话 + 提问**。画像/类型/匹配全部走固定规则脚本（零 AI 调用、零成本），只有「关系复盘解释 + 开放式提问」才调 AI，且**按需触发 + 结果缓存**，成本压到每月几块钱。
- **规则先行**：匹配和画像先用「问卷打分 + 规则」实现，验证有效后再上推荐算法/向量检索。不一开始追复杂算法。

## 2. 系统架构

```
用户浏览器（手机/PC）
      │
      ▼
 Next.js 前端（Vercel）
      │  ├─ 页面渲染 + 交互
      │  └─ API Routes（服务端逻辑：AI 复盘、问卷计分）
      ▼
 Supabase
      ├─ Postgres（业务数据）
      ├─ Auth（登录/实名）
      ├─ Realtime（私信）
      └─ Storage（照片、头像）
      ▼
 第三方：Claude API（AI）· 腾讯/阿里内容安全（审核）
```

安全边界：所有数据读写走 Supabase **RLS**，客户端不能直接越权读别人的私密档案。AI 复盘、问卷计分等逻辑放 API Routes（服务端），不放前端。

## 3. 数据模型（核心表）

> 完整字段以 `id`、`created_at`、`updated_at` 为标配，下面只列关键业务字段。

**账号与资料**
- `profiles`：`user_id`、`nickname`、`gender`、`birth_date`、`location`、`photos[]`、`bio`、`relationship_goal`（择偶阶段/意愿）、`verified`（实名/认证标记）、兴趣标签 `interests[]`。敏感项（身高/收入/职业等）用户可选是否公开。

**认知系统（四层认知模型）**
- `questionnaires`：问卷模板。`title`、`category`（消费观/家庭观/沟通/关系节奏…）、`version`。
- `questions`：`questionnaire_id`、`text`、`type`（单选/量表/场景题）、`options(jsonb)`、`dimension`（映射到哪个认知维度）。
- `question_answers`：`user_id`、`question_id`、`answer(jsonb)`、`version`（支持修改历史）。
- `user_insights`：画像结果。`user_id`、`layer`（1 成长背景 / 2 自我认知 / 3 行为模式 / 4 择偶需求）、`dimension`、`score`、`evidence`（依据）、`updated_at`。
- `preferences`：动态偏好。`user_id`、`dimension`、`current_value`（当前真实倾向）、`explore_min` / `explore_max`（主动探索区间）——对应"向左/向右调整"。

**人性百科（内容壁垒）**
- `type_cases`：人格类型词条。`slug`、`name`（如"低自我评价型"）、`formation`（成因）、`typical_behaviors`、`relationship_conflicts`、`examples[]`（案例）、`related_questionnaire_id`、`status`（审核态）。

**社区与内容**
- `posts`：`user_id`、`title`、`content`、`category`（纯爱/复盘/讨论/社会观察）、`tags[]`、`is_anonymous`、`status`（审核态）。
- `post_likes`、`comments`：互动。
- `growth_records`：成长档案。`user_id`、`type`（初始认知/交往记录/复盘/长期关系）、`content`、`ai_analysis`、`visibility`（私密/匿名/公开）。

**匹配与沟通**
- `matches`：`from_user_id`、`to_user_id`、`type`（like/interest）、`status`、`matched_at`。
- `conversations`（`user_a`/`user_b`）、`messages`（`conversation_id`、`sender_id`、`content`）。

**治理**
- `moderation_reports`：举报、审核流水。

## 4. 页面 / 路由结构

**公开（未登录）**
- `/` 落地页 + 社区首页
- `/cases` 人性百科库、`/cases/[slug]` 人格词条详情（内容入口，做 SEO）
- `/posts/[id]` 帖子详情
- `/auth/*` 登录/注册

**用户（登录后 `/app`）**
- `/app/discover` 匹配推荐
- `/app/questionnaire` 问卷
- `/app/insights` 我的认知画像（四层）
- `/app/preferences` 偏好实验室（可调区间滑块）
- `/app/profile` 个人主页/资料
- `/app/growth` 成长档案
- `/app/messages` 私信

## 5. API 设计（核心）

- `POST /api/questionnaire/submit` 提交/更新作答 → 服务端计分写 `user_insights`、`preferences`
- `GET /api/insights` 获取画像（含"当前倾向 vs 探索区间"）
- `GET /api/matches` 推荐列表（规则匹配起步）
- `POST /api/likes` 表达兴趣
- `GET/POST /api/growth` 成长档案 CRUD
- `POST /api/ai/review` 触发 AI 关系复盘（Claude，输入结构化记录，输出开放式提问 + 人话解释）
- `GET/POST /api/posts` 社区
- `POST /api/moderation/report` 举报

## 6. 核心功能实现要点

**问卷 → 画像**：作答不直接定级，按 `dimension` 加权落到四个 `layer`，产出连续分数 + 依据；同时写"探索区间"。用户可随时改，保留 `version` 历史。

**匹配**：先用规则（基础条件过滤 → 兴趣/偏好相似度打分 → 双向意愿），上线后再考虑算法/向量。

**AI 复盘**：只传结构化数据给 DeepSeek，Prompt 强制"不诊断、不贴标签、只提问 + 解释"，输出走内容安全审核后才展示；**按需触发（用户主动点）+ 结果缓存**，控制成本。

**隐私分层**：三态（私密/匿名/公开）用 RLS 强制；问卷与画像默认私密；公开内容必须用户显式授权。

## 7. MVP 分阶段路线（解决冷启动）

- **Phase 0（先做）**：`type_cases` 人性百科 + 问卷 + 认知画像结果页。**纯单边，不做匹配/私信**。靠"测测我是什么类型 / 看看这世上有哪些人"获客，无网络效应死穴。
- **Phase 1**：匹配推荐 + 兴趣表达 + 私信 + 个人主页。
- **Phase 2**：AI 关系复盘 + 偏好实验室（可调区间）。
- **Phase 3**：成长档案 + 匿名/公开案例社区 + 长期追踪。

## 8. 上线 / 合规（写代码前专项调研）

- ICP 备案、婚恋/社交平台资质、实名认证方案。
- 内容审核接入、未成年人保护、隐私政策/用户协议。
- 数据本地化（国内服务器/合规存储）。
