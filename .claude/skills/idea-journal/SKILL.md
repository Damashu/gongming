# Idea Journal（想法记录 + 梳理 + 可行性分析）

目标：让用户的每个想法都被清楚记录、可追溯、可复盘，并给出可行性判断。用中文、简洁、少废话。

## 每次用户分享想法时的流程

### 1. 记录
- 追加到当天文件 `ideas/YYYY-MM-DD.md`（不存在就按 `ideas/_TEMPLATE.md` 的格式新建）。
- 每个想法一个「## 想法：[标题]」小节，包含：
  - 一句话描述
  - 详细说明（用户原话要点 + 背景）
  - 目标用户 / 核心场景
  - 关键问题 / 疑点
  - 关联想法（用 `[[YYYY-MM-DD#标题]]` 链接到相关条目）

### 2. 更新索引
- 在 `ideas/INDEX.md` 的「想法清单」表格加一行，在「时间线」当天小节加一条。

### 3. 可行性分析（关键）
对想法做快速三问，并给出结论：
1. **技术可行性**：能不能用现有技术低成本做出来？难点在哪？
2. **市场 / 渠道**：目标用户在哪？怎么获客？有没有现成竞品？
3. **成本 / 风险**：要花多少钱多少时间？最大的坑是什么？

结论用状态标注：🟢 可行 / 🟡 待评估 / 🔴 暂缓，并写一句「建议下一步」。

### 4. 记忆
- 只把「已立项的决策、技术选型、关键约束」写入 memory（type: project）。
- 不重复记录 CLAUDE.md 或 ideas/ 里已有的内容。

### 5. 回复用户
- 简洁总结：记录了什么、可行性结论、建议的下一步。
- 如果想法足够具体，主动提出：要不要我上外网调研框架 / 竞品 / 上线渠道。
